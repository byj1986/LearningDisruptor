## 阅读要点

以下为按本日实验重新组织的学习笔记：

- count++包含读取、计算、写回；单次读写的原子性不代表整个更新原子。Interlocked适合指定的原子更新，lock可以把多步不变量一起保护。
- 本项目使用.NET 10，可学习专用System.Threading.Lock；若用object锁则理解Monitor路径。两种选择都要求参与线程共享同一个用于保护该资源的锁实例。

## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 继续第1天并发项目，单独增加共享计数实验。设4个工作任务、每个100000次，计数器每轮重置，预期总数先写在记录中。

### 10～30分钟：定向阅读

- [ ] 阅读临界区与原子操作；在纸上让两条线程都读到0，再分别写回1，标出一次更新如何丢失。

### 30～50分钟：最小实验

- [ ] 实现无保护的共享++，等待4个任务完成后才读总数。至少重复10轮，记录每轮实际值；不用逐次打印扩大干扰。

### 50～75分钟：扩展实现

- [ ] 实现lock版本，所有任务共享同一个锁对象；再实现Interlocked版本。只改变递增方式，保持任务数、次数、等待和计数类型相同。

### 75～105分钟：边界与对照

- [ ] 再测1个任务与4个任务两种配置。逐项核对结果；如有时间，可故意给每个任务不同锁，验证它保护不了同一计数器。

### 105～120分钟：验收与复盘

- [ ] 比较三种写法的正确性证据，写出锁对象必须共享的理由。粗略耗时只作观察，不把这次练习包装成完整性能测试。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 单任务对照 | 1×100000 | 无保护也应为100000 |
| 共享原子递增 | 4×100000，10轮 | lock与Interlocked每轮均为400000 |
| 无保护/不同锁 | 4×100000 | 可能出现丢失；即使偶尔正确也不能证明安全 |

## 卡住时先检查

- 正确版本也出错时，检查是否漏await、是否在任务完成前重置或读取计数器。
- 无保护版本没有失败时，用纸面交错证明风险；可以增加争用，不要求某次运行一定出错。
