## 本日核心概念

## 今日完成后应交付什么

## 阅读要点

以下为按本日实验重新组织的学习笔记：

- 有界Channel限制缓冲数量；满时等待使生产方感受到消费速度。正常完成先结束写入，再读完已接受的数据；异步写入等待不等于占着线程休眠。
- 取消是合作协议：发出请求不等于所有工作已停止。停止接收、排空和取消处理要分别定义，并记录已接受、已处理及未完成数量。

## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 10～30分钟：定向阅读

- [ ] 阅读“满时等待”和“正常结束”两条路径。画出生产者完成写入、消费者读完剩余消息、主控等待双方的先后关系。

### 30～50分钟：最小实验

- [ ] 实现发布编号0～9999；消费方校验顺序，最终完成后检查总数与编号和49995000。正常路径不依赖取消来退出。

### 50～75分钟：扩展实现

- [ ] 做容量2的受控实验：消费者取走第一条后停在信号处，再把队列填满。观察下一次WriteAsync未完成，释放消费者后观察它完成。

### 75～105分钟：边界与对照

- [ ] 另做取消实验。先停止继续生产，再取消处理并等待任务退出；记录已接受、已完成及未完成数量，不强求取消后仍全部处理。

### 105～120分钟：验收与复盘

- [ ] 将正常完成与取消记录放在一起，说明谁停止接收、谁停止处理以及还有哪些消息。所有异常都在主控有明确观察位置。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 正常完成 | N=10000，容量64 | 10000条且顺序正确，编号和49995000 |
| 容量约束 | 容量2，信号暂停消费者 | 满后写入等待；释放后恢复 |
| 取消 | 生产中或消费中请求取消 | 任务可退出，已接受=已完成+未完成，单消费者无重试 |

## 卡住时先检查

- 生产者抛错后也要结束写入或通知失败，否则消费者可能一直等新消息。
- 已接受计数应在成功写入后增加；取消中的一次尝试不自动算已接受。
