## 阅读要点

以下为按本日实验重新组织的学习笔记：

- 原子性关心操作能否被拆开，可见性和排序关心另一线程能观察到什么。Volatile提供特定读写排序语义，不把++变成原子操作，也不无条件保证读取立刻看到最新值。
- CAS重试与事件通知是两种不同工作：前者竞争一次条件更新，后者协调等待者。每轮用独立状态，避免把复位与复用协议混进单次发布实验。

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

- [ ] 继续并发项目，建立一个单次发布练习：一条线程填写两个普通数据字段，再通知另一条线程读取。每一轮都创建独立状态，避免复位协议混入实验。

### 10～30分钟：定向阅读

- [ ] 阅读并写出三个独立问题：一次更新能否被拆开，另一线程何时能观察，数据与标志能否按协议排序。分别对应本日的三个概念。

### 30～50分钟：最小实验

- [ ] 用Volatile.Write发布就绪标志；读取方用Volatile.Read观察。数据写在发布前、数据读在观察成功后；等待使用超时和适当自旋退让。

### 50～75分钟：扩展实现

- [ ] 用ManualResetEventSlim重做通知，运行100轮并检查数据。主控必须等待两条工作流程结束；超时作为失败，不继续读未就绪数据。

### 75～105分钟：边界与对照

- [ ] 用CompareExchange循环手写递增：读取旧值、计算新值、比较交换，失败后重试。用第2天4×100000配置核对，并另记重试次数。

### 105～120分钟：验收与复盘

- [ ] 分别解释通知、可见性与原子复合更新；指出“所有轮次通过”是实验结果，协议正确性仍需依据内存语义说明。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 单次数据发布 | 100轮，每轮独立状态 | 观察到就绪后两个字段均正确 |
| 等待超时 | 故意不发通知，超时500ms | 报告超时并结束，不把默认数据当成功 |

## 卡住时先检查

- 不要在一轮尚未结束时复用并重置就绪标志。
- CAS重试计数本身也属于共享状态；可按任务分别累计后汇总，避免再引入数据竞争。
