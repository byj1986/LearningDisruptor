- 书A第1章只区分并发、并行、异步，第2章只读等待一组任务与异常传播；书B第26章看线程启动、Join、线程池。

## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 在已有并发项目中新建一个自己命名的练习方法。先让主流程同步计算1到100000之和，打印开始、结束、线程编号、结果，保留为参考。

### 10～30分钟：定向阅读

- [ ] 带着两个问题阅读：谁负责执行工作，谁代表工作完成？写出同步计算、显式Thread、Task.Run三种方式各自的启动与等待办法。

### 30～50分钟：最小实验

- [ ] 把同一计算交给一个Thread，主流程在启动后打印一条标记，再Join。重复3次；保证工作结果一致，观察两条流程标记的先后。

### 50～75分钟：扩展实现

- [ ] 把同一计算改为Task.Run；先等待一个任务，再同时启动两个独立任务并等待全部完成。结果分别保存，避免此时引入共享累加器。

### 75～105分钟：边界与对照

- [ ] 分别做Sleep与Delay小实验：Sleep(500)前后打印；再启动Delay(500)，立刻打印主流程标记，最后await。随后在Task中抛出一个已知异常，确认等待方能收到它。

### 105～120分钟：验收与复盘

- [ ] 整理四个实验的事件顺序与耗时；用自己的话回答本日问题。保存结果和运行命令，再在Release下重跑一次，不据此给出性能排名。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 求和参考及两种执行方式 | 1～100000 | 三种结果均为5000050000，使用long保存 |
| 等待全部任务 | 两个独立任务 | 主流程结束标记在两者完成之后 |
| 异步完成与异常 | 500ms等待；一个主动抛出的异常 | 耗时允许调度偏差；等待方观察到异常 |

## 卡住时先检查

- 缺少结束标记时，先检查是否等待了所有任务，而不是增加Sleep。
- 异步入口可自行改为async Task Main；普通业务异步方法返回Task，避免用async void承载本日练习。
