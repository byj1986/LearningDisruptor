## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 先不改程序，在源码中找到等待入口、遍历循环、回调调用和进度发布四个位置，记录各自变量含义。

### 10～30分钟：定向阅读

- [ ] 阅读一批已就绪事件从lo到hi的处理流程，标出何时读事件、何时通知批末、何时允许上游复用。

### 30～50分钟：最小实验

- [ ] 在自己的处理器中受控暂停一个回调，同时观察处理器对外序号。区分“正在回调中的事件”和“已对外公布完成的事件”。

### 50～75分钟：扩展实现

- [ ] 对照第9天的批次分布与第12天的阶段依赖，找出其源码依据；不要预设每处理一条就立即推进一次可见进度。

### 75～105分钟：边界与对照

- [ ] 对照第15天查看回调抛错、等待取消与Halt的路径，分别记录是否推进、继续或退出；用小样本验证你选用的异常策略。

### 105～120分钟：验收与复盘

- [ ] 把主循环改写为不超过12行的文字或伪代码说明，标记异常边界；不复制整段库实现。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 正常批次 | 已就绪连续小批 | 逐条回调，批末语义与可用范围对应 |
| 回调内暂停 | 信号暂停一个事件 | 可观察在处理与已公布进度的差别 |
| 错误/停止 | 沿用小规模异常与Halt用例 | 实际行为能对应到所用版本的源码分支 |

## 卡住时先检查

- 回调里发出通知和处理器已公布进度不是同一时刻；观察代码要写清口径。
- 调试器停住线程会改变时序，本日用于理解路径，不用于测延迟。
