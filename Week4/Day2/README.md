## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 在纸上约定初始末端消费序号-1、容量8。分别画出申请到7和申请到11两种状态，先判断哪些旧数据仍占槽位。

### 10～30分钟：定向阅读

- [ ] 阅读申请路径，把快速路径、容量不足路径、刷新最慢消费者进度路径分别标出来；用自己的话解释每条分支。

### 30～50分钟：最小实验

- [ ] 逐行推演末端消费序号3、已申请到11时申请12的过程：写出12映射的槽位、回绕点以及将覆盖的旧序号。

### 50～75分钟：扩展实现

- [ ] 先用第10天暂停实验核对满与恢复；要精确控制进度3/4时，另建Sequencer与手动gating Sequence模型，不能修改运行中真实处理器拥有的序号。

### 75～105分钟：边界与对照

- [ ] 在独立模型中依次推进gating进度到4和5，预测能申请到哪里，再用TryNext核对。将预测、实际结果和源码条件写在同一表格。

### 105～120分钟：验收与复盘

- [ ] 画一张Next到Publish的流程图，区分消费者保留空间和生产者发布可见性两类限制。用图回答为什么需要末端消费者进度。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 初始容量 | consumer=-1，已申请到7 | 再申请8暂无可用槽位 |
| 满的推演 | consumer=3，已申请到11 | 申请12失败或等待 |
| 释放一个位置 | consumer推进到4 | 在其余条件不变时可申请12 |

## 卡住时先检查

- 统一“最后已完成序号”和“下一待处理序号”的口径，避免差一错误。
- 推演多消费者时使用约束槽位复用的最慢末端进度，不随意选最快处理器。
