## 阅读要点

以下为按本日实验重新组织的学习笔记：

- 线程是否得到执行由调度与可用资源共同决定。自旋、让出和阻塞会带来不同CPU成本，不能由一轮实验推导固定延迟保证。
- 分别观察等待新事件和等待前置阶段的路径。生产者满时策略仍需单独定义，不能从消费者等待策略的名字推断出来。

## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 先写实验表：Blocking、Yielding、BusySpin三种策略；保持容量1024、单生产单消费和处理逻辑一致。

### 10～30分钟：定向阅读

- [ ] 阅读每种等待循环中阻塞、让出与自旋的位置，找出关闭通知如何到达等待方，并说明依赖等待是否走同一路径。

### 30～50分钟：最小实验

- [ ] 每个策略独立启动运行，先空闲3秒；记录墙钟与进程CPU时间增量，统一是否按逻辑处理器数归一化的CPU口径。

### 50～75分钟：扩展实现

- [ ] 再以较低速率发送，再测试短突发；记录实际发送速率与完成耗时，尚不做正式P99排名。每次运行都完整关闭旧处理器。

### 75～105分钟：边界与对照

- [ ] 把单阶段改为带慢前置阶段的小流水线，观察等待依赖时的CPU；只变拓扑，业务输入和测量方式保持一致。

### 105～120分钟：验收与复盘

- [ ] 填写策略×负载矩阵，分别给出观测值和原因推测。说明CPU预算、可用核心和系统负载为何会影响选择。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 空闲 | 各策略3秒 | 均可关闭；CPU可能不同，记录实测 |
| 低速与突发 | 三种策略同输入 | 事件正确完成，负载与口径一致 |
| 依赖等待 | 加入慢前置阶段 | 同时观察CPU，不假定阻塞策略在所有等待中都休眠 |

## 卡住时先检查

- 空闲CPU实验中不要持续打印；旧消费者没停会污染下一组。
- Windows线程让出与休眠的行为受调度影响，不把某个等待时长写成硬保证。
