## 本日核心概念

- 批量申请、填充、发布。
- endOfBatch 是当前可消费批次的结束，不保证与发布批次一一对应。

## 今日完成后应交付什么

三种批量发布的结果、尾批校验、消费批次大小记录。

## 阅读要点

- Publication Options的Batches；Event Handlers的endOfBatch语义。
- 区分一批申请的序号范围和消费者一次可处理的连续范围。

## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 确定总数100003、每条金额100分，发布批量大小依次为1、16、64；先算最后不足一批如何处理。

### 10～30分钟：定向阅读

- [ ] 阅读批量申请和批量发布的上下界，画出一次申请的lo、hi及包含多少槽位。容量1024，单批不能超过容量。

### 30～50分钟：最小实验

- [ ] 手写按剩余数量确定本次批量的循环，逐个填好已取得槽位；保留异常下所有已申请事件都有明确状态的规则。

### 50～75分钟：扩展实现

- [ ] 消费者记录批次结束次数、每个消费批次的大小及总和。只在批次结束汇总一次，业务结果必须与逐条方式一致。

### 75～105分钟：边界与对照

- [ ] 分别让生产者较慢、消费者较慢各运行一轮；观察发布批次与消费批次是否总相同。少量日志只用于解释，正式计数轮移除。

### 105～120分钟：验收与复盘

- [ ] 汇总三种发布大小的正确性与消费批次分布。解释batch边界变化的原因，不要求测出固定加速比。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 整批与尾批 | N=100003，batch=1/16/64 | 总数100003，金额10000300分 |
| 尾批 | 按每次剩余数量申请 | 最后一批无重复、遗漏或多发 |
| 消费批次 | 改变生产/消费相对速度 | 消费批次可能变化，总事件与汇总不变 |

## 卡住时先检查

- 避免最后一批仍强行发布64条。
- 先验证全部正确，再比较调用与协调开销；逐条输出会干扰批次观察。
