## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 切换订单项目，先写出生命周期草图：创建事件工厂、注册处理器、启动、发布、确认完成、停止。容量先固定1024。

### 10～30分钟：定向阅读

- [ ] 带着对象在哪里创建、哪个线程调用处理器两个问题读入门示例。只记最小所需API，暂不增加多阶段和复杂泛型封装。

### 30～50分钟：最小实验

- [ ] 手写OrderEvent与一个处理器，字段先只有编号和整数分金额。发布0～9，每条金额100；打印少量线程编号与事件信息。

### 50～75分钟：扩展实现

- [ ] 增加可靠的完成通知或进度观察；主控等待10条处理完成后调用有超时的正常关闭。另做零消息启动关闭场景。

### 75～105分钟：边界与对照

- [ ] 改为100000条，移除逐条打印。消费方累计计数、编号和及金额总和；用同步完成通知确保主控读取统计时数据已可见。

### 105～120分钟：验收与复盘

- [ ] 记录最小调用顺序、创建对象数量与处理线程。保存运行命令和三项校验值，确认程序能够独立退出。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 少量消息 | N=10，每条100分 | 数量10、编号和45、金额1000分 |
| 连续消息 | N=100000 | 数量100000、编号和4999950000、金额10000000分 |
| 零消息 | N=0 | 启动关闭可结束，不等待不存在的第1条 |

## 卡住时先检查

- 累计编号和用long，避免100000条时int溢出。
- Shutdown前先停止发布；它的返回也不等于所有处理线程已最终终止，线程生命周期观察要另行确认。
