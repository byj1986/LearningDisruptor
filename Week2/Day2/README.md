## 本日核心概念

- 申请序号、填充槽位、发布序号的协议。
- 发布作用域退出会发布，不等于事务回滚。

## 今日完成后应交付什么

两种发布写法、两类失败边界和一张计数关系表。

## 阅读要点

- Publication Options只读Next/Publish及发布作用域。
- 根据6.0.1理解作用域Dispose的发布行为；先区分输入拒绝与已取得槽位后的失败。

## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 沿用最小订单项目，定义尝试、取得槽位、发布、有效消费、无效消费五类计数；写出它们应满足的关系。

### 10～30分钟：定向阅读

- [ ] 阅读发布协议，画出Next成功之后、字段填写期间、Publish之后三段。标出异常分别发生在哪一段会影响已取得序号。

### 30～50分钟：最小实验

- [ ] 手写显式Next/Publish版本，在finally完成发布。取得槽位后先设置无效状态，字段全部写好后再置有效。

### 50～75分钟：扩展实现

- [ ] 再写发布作用域版本。使用相同输入核对结果；在填充中间故意抛错，确认退出作用域仍会发布，而不是撤销序号。

### 75～105分钟：边界与对照

- [ ] 分两轮运行：一轮在取得槽位前拒绝非法输入，一轮取得槽位后模拟一次失败。捕获生产错误并继续，让消费者识别无效槽位。

### 105～120分钟：验收与复盘

- [ ] 核对两轮计数，把发布协议和业务有效性分开解释。确认后续正常事件不会因本次失败永久停住。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 全部正常 | 10次尝试 | 发布10、有效10 |
| 取得前拒绝 | 10次尝试，拒绝1次 | 发布9、有效9、拒绝1 |
| 取得后失败 | 10次取得槽位，其中1次填充失败 | 发布10、有效9、无效1，后续事件可消费 |

## 卡住时先检查

- 无效标志必须在填充前清理，避免复用槽位保留上一条有效状态。
- 错误注入不能破坏finally发布；主控等待也必须有超时。
