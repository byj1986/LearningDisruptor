## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 容量设8，用信号使消费者停在处理第一条的回调中。生产者发布序号0～7，确认末端进度尚未释放容量。

### 10～30分钟：定向阅读

- [ ] 阅读Next与TryNext的满时行为；先预测第9次申请是等待还是立即失败，分别设计一轮而不是混用。

### 30～50分钟：最小实验

- [ ] 在独立生产任务中执行等待式申请，主控观察其未完成；随后释放消费者，等待生产任务及消费全部完成。

### 50～75分钟：扩展实现

- [ ] 另起一轮使用TryNext尝试获取槽位，满时记录拒绝，不读取无效的out序号。之后加入固定截止时间与退让的重试策略。

### 75～105分钟：边界与对照

- [ ] 为重试区分业务尝试数与内部申请次数；恢复消费者后对账成功、拒绝、已消费，确保每条业务输入只进入一个最终分类。

### 105～120分钟：验收与复盘

- [ ] 说明持续入速大于处理能力时，容量8换成1024能改变什么。无论实验通过或失败，finally都释放暂停信号并收尾。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 满时等待 | 容量8，消费者暂停，第9次申请 | 生产任务等待；恢复后可继续 |
| 满时尝试 | 相同配置，TryNext | 返回失败，不发布未取得的序号 |
| 重试与拒绝 | 每条输入只有一次最终分类 | 业务尝试=成功发布+最终拒绝，完成后发布=消费 |

## 卡住时先检查

- Next的外部等待超时不等于取消了Next；必须释放消费者，收回仍在运行的生产任务。
- 协调实验不能让主控自己阻塞在Next上，否则它无法再发恢复信号。
