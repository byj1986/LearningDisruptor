## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 为现有订单项目列配置项：数量、容量、生产者数、拓扑、等待策略、错误注入和关闭截止时间。先挑3项做最低可运行入口。

### 10～30分钟：定向阅读

- [ ] 阅读已有生命周期记录，列出每次运行都要重建的状态与可复用的纯业务计算，避免上一轮计数或取消标志遗留。

### 30～50分钟：最小实验

- [ ] 把创建、注册、启动、生产、等待、关闭整理成清晰流程；非法容量与未知模式在启动前明确报错。

### 50～75分钟：扩展实现

- [ ] 依次挂入正常、无效订单、慢消费者、突发输入四种命名场景；每次输出配置、接受/处理分类和退出原因。

### 75～105分钟：边界与对照

- [ ] 对每个场景先运行小数据，再运行较大数据；连续运行两次，核对计数重置及单线程参考结果。

### 105～120分钟：验收与复盘

- [ ] 在README记录每个场景的实际命令、预期关系和结果。确保下一天可直接复用正常单生产单消费场景。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 可重复运行 | 同配置运行两次 | 结果一致，状态不累积 |
| 场景集合 | 正常/无效/慢/突发 | 各自分类与退出条件明确 |
| 非法配置 | 非2的幂容量或未知模式 | 启动前报告问题，不留下处理线程 |
