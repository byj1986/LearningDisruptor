## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 两边固定容量1024、单生产单消费、满时等待、同一业务计算；移除热路径日志和完整性集合，保留完成计数及校验和。

### 10～30分钟：定向阅读

- [ ] 阅读测量API，写明CPU归一化口径及分配量是进程累计差值。预先分配记录空间，区分初始化、预热与测量区间。

### 30～50分钟：最小实验

- [ ] 用Release且不附加调试器运行。预热5秒后先排空并重置统计，再测至少10秒；最后停止生产并等到全部消费完成，尾部排空时间也计入。

### 50～75分钟：扩展实现

- [ ] 每个实现独立进程运行5轮，交替两种实现顺序；记录已处理数、实际秒数、吞吐量、CPU、分配差值及各代GC差值。

### 75～105分钟：边界与对照

- [ ] 计算每轮events/s与分配bytes/event，报告5轮原始值和中位数、范围；若有异常轮，保留并解释，不能只挑最快一轮。

### 105～120分钟：验收与复盘

- [ ] 核对业务结果与配置一致。写一句有边界的结论：本机、该配置、该工作量下的结果，列出后台任务或温度等未控制因素。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 测量轮数 | 2实现×5轮，预热5秒、测量至少10秒 | 每轮有独立原始记录与正确结果 |
| 吞吐量分母 | 完成N条所用墙钟总时间 | 包含排空，不仅是生产循环耗时 |
| 跨线程分配 | 进程累计分配量前后差 | 同口径比较，扣清初始化/记录开销的边界 |

## 卡住时先检查

- 时间区间与事件计数必须对应；不能用10秒生产量除以不含排空的10秒假装完成吞吐量。
- 两种实现不要同时跑而争用CPU；单独运行并记录环境。
