## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 先规定三个时刻：计划发送、实际尝试发布、最终消费完成。主指标为尝试到完成；另外记录计划到尝试的发送滞后。

### 10～30分钟：定向阅读

- [ ] 阅读时间戳单位；用预先准备的1～100序列验证最近秩百分位：P50为50、P99为99。确认ticks转毫秒用Frequency。

### 30～50分钟：最小实验

- [ ] 预分配事件测量存储，按唯一编号记录时间戳；排序、统计、输出放在测量区间外。另做不打时间戳对照估计观测开销。

### 50～75分钟：扩展实现

- [ ] 依据第23天结果选明显低于容量、接近处理能力的目标输入速率，再加突发场景。记录目标/实际速率、样本数及发送滞后，不为追赶而无限创建Task。

### 75～105分钟：边界与对照

- [ ] 在一组固定目标负载下仅改变容量，例如1024和16384；两种实现分别运行，报告P50/P99/最大值和未完成/拒绝情况。

### 105～120分钟：验收与复盘

- [ ] 解释两条延迟口径及负载维持情况。若发送端因背压低于目标速率，标明欠发，不能拿减少采样后的好看P99代表原目标负载。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 统计自检 | 1～100，最近秩规则 | P50=50，P99=99 |
| 负载集合 | 低负载/近饱和/突发 | 每组记录目标速率、实际速率与样本数 |
| 容量单变量 | 相同目标负载、两个容量 | 报告延迟与发送滞后，不预设越大越快 |
