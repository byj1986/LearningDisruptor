## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 进入Channel订单对照项目，借鉴第4天。写对照表：同容量、相同输入字段、业务计算、生产者/消费者数量和满时等待。

### 10～30分钟：定向阅读

- [ ] 阅读Channels配置，确认正常完成与取消边界；记录两个实现的对象所有权和分配方式，作为报告的一部分。

### 30～50分钟：最小实验

- [ ] 手写等价载荷与同样的整数分业务计算，先跑1000条。不能把Disruptor可复用槽位引用直接送进Channel并提前归还。

### 50～75分钟：扩展实现

- [ ] 扩至100000条，核对数量、编号和、金额及费用；另跑无效输入小样本，确认两边业务规则一致。

### 75～105分钟：边界与对照

- [ ] 分别减慢消费者，确认两个版本都等待而非悄悄丢消息；用相同停止条件结束。仅把真实配置差异写明，不强求内部结构相同。

### 105～120分钟：验收与复盘

- [ ] 完成比较规格，列出哪些成本属于整个实现、哪些是队列机制；准备下一天固定配置的运行命令。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 业务一致 | 100000条正常订单，每条金额100分、费用10分 | 数量100000、编号和4999950000、金额10000000分、费用1000000分 |
| 过载语义 | 容量1024，慢消费 | 两边都等待，不丢已接受事件 |
| 生命周期 | 多轮运行与正常完成 | 两边均排空退出，无槽位引用被提前复用 |

## 卡住时先检查

- Channel内保存的可变对象必须有明确所有权。
- 报告中明确是整条实现对比；有不同分配策略时，不把所有差异都归因于队列算法。
