## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 先恢复单消费者，固定100000条；每10000条在指定回调抛一次业务异常，共10次，先定义成功、失败、未完成的统计边界。

### 10～30分钟：定向阅读

- [ ] 阅读异常处理和有超时Shutdown。画正常关闭与故障关闭两条流程；注意Shutdown不负责等待处理线程最终终止。

### 30～50分钟：最小实验

- [ ] 实现记录后继续的异常策略，生产者正常结束后排空；检查99990成功、10失败，并确认错误后的后续编号也已到达。

### 50～75分钟：扩展实现

- [ ] 另起独立运行实现停止策略，故障信号通知主控；生产端使用TryNext加取消/截止检查，主控停止接收并报告未完成数，避免停住消费者后仍有生产者卡在Next。

### 75～105分钟：边界与对照

- [ ] 再让消费者受控暂停，验证Shutdown的截止时间会失败而不是永远等待；finally释放信号或调用Halt收尾，不能丢下仍阻塞的发布任务。

### 105～120分钟：验收与复盘

- [ ] 记录故障位置、最后处理序号、生产与消费终态。对照已接受=成功+失败+未完成；停止模式不要假装消息已全部处理。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 继续策略 | 100000条，10个回调错误 | 成功99990、失败10、未完成0 |
| 停止策略 | 指定编号致命失败 | 有明确故障与未完成统计，最终分类可对账 |
| 关闭超时 | 消费者暂停，固定截止时间 | 观察TimeoutException并明确收尾，不无限等待 |

## 卡住时先检查

- 异常通知也需要同步，不能靠普通共享bool和固定Sleep猜测。
- 在多阶段场景中异常后是否继续下游属于业务策略；本日先在单消费者验证清楚，不宣称自动保证业务事务。
