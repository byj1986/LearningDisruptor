- 多个普通事件处理器分别接收同一个事件。
- 广播与队列竞争消费的区别；共享事件的写入所有权。

## 今日完成后应交付什么

## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 继续订单项目，画生产者分发给A和B的图。设10000条、每条100分；先预测A/B分别应收到多少条。

### 10～30分钟：定向阅读

- [ ] 阅读广播语义和处理线程，写出它与一个Channel被两个消费者分摊的区别。给两个处理器分别命名，暂不修改事件字段。

### 30～50分钟：最小实验

- [ ] A累计数量，B累计金额，二者各自维护统计和完成信号；主控等待两个处理器都完成再读取结果。

### 50～75分钟：扩展实现

- [ ] 增加各自编号校验，先用10条少量输出观察两处理器顺序，再用10000条移除日志运行。

### 75～105分钟：边界与对照

- [ ] 让B按受控规则变慢，观察A可先走但不能无限绕过B释放容量；记录两个阶段完成时刻与生产者申请等待。

### 105～120分钟：验收与复盘

- [ ] 对照第4天写出广播与竞争消费的投递次数表。说明A/B各自统计变量为什么可以由所属处理线程独占更新。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 广播数量 | 10000条，A/B并行 | A、B各收到10000条 |
| 独立业务 | 金额每条100分 | B金额1000000分，各自编号无遗漏 |
| 慢分支 | 减慢B | A可领先；B仍约束槽位最终复用 |

## 卡住时先检查

- 不要让A/B同时更新同一个普通计数器。
- 广播比较中总处理次数是2N，不要拿它与只处理N次的队列吞吐量直接比较。
