## 本日核心概念

- 单生产者与多生产者配置。

## 阅读要点

## 120分钟执行顺序

每段完成后再进入下一段；记录预测与实际的差异，数值预期不是已经测得的结果。

### 00～10分钟：准备与预测

- [ ] 设计ProducerId为0/1、LocalId为0～49999；组合业务编号为ProducerId×50000+LocalId，唯一范围0～99999。

### 10～30分钟：定向阅读

- [ ] 阅读并选用多生产者配置，明确每个生产者自身顺序发布、每次取得槽位完成填充后发布。

### 30～50分钟：最小实验

- [ ] 先以两个生产者各10条运行，用信号让二者接近同时开始；消费者打印业务编号、生产者编号及框架序号。

### 50～75分钟：扩展实现

- [ ] 扩至各50000条，用单消费者维护唯一性检查及各生产者上次LocalId；记录重复、遗漏和生产者内部逆序。

### 75～105分钟：边界与对照

- [ ] 重复运行3轮，并只减慢一个生产者；检查总数、唯一集合与局部顺序，观察全局业务编号是否仍单调。

### 105～120分钟：验收与复盘

- [ ] 保留两类序号对照，说明为何发布序号能连续而组合业务编号在消费中可以跳跃。性能实验前移除集合校验开销。

## 验证场景与预期

| 场景 | 输入或条件 | 通过标准或应观察的现象 |
| --- | --- | --- |
| 小样本 | 2×10 | 20条均唯一，便于观察交错 |
| 完整样本 | 2×50000，3轮 | 100000条，0遗漏、0重复、局部顺序正确 |
| 不同速度 | 只减慢生产者0 | 结果完整；不同生产者业务编号不要求全局递增 |

## 卡住时先检查

- 组合业务编号要在生产者本地计算，再写自己的槽位，避免共享可变输入。
- 不要把两个生产者同时写同一个预先共享OrderEvent对象当成槽位填充。
